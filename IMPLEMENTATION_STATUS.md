### Phase 2A — Backend foundation and account/session layer (branch `madvith`)

- **Typed settings** (`app/core/config.py`): pydantic-settings; app env, public URLs,
  CORS origins, session/token-crypto secrets, TTLs, GitHub OAuth/API base URLs
  (configurable so automated tests never touch the network), DB URL, storage root.
- **Logging** (`app/core/logging.py`): JSON lines with request IDs and credential
  redaction (`access_token`, `client_secret`, `authorization`, `cookie`, etc.).
- **Request IDs** (`app/core/middleware.py`): per-request UUID, `X-Request-ID` header,
  structured request logs. Exception handlers emit the same ID in error envelopes.
- **Error envelope** (`app/core/errors.py`): `ApiError` with stable codes, request
  validation → `VALIDATION_ERROR` 400, 404s, and generic 500 `INTERNAL_ERROR` that
  logs internals but never leaks them.
- **DB layer**: SQLAlchemy 2 models (`User`, `GitHubCredential`, `UserSession`,
  `OAuthState`, `GitHubInstallation`, `Project`, `SourceSnapshot`, `AnalysisRun`,
  `Report`) with ownership/index constraints; session management with
  commit/rollback/close lifecycle; Alembic with one autogenerated migration
  applied to a clean SQLite DB.
- **Security**: Fernet token encryption (SHA-256-derived key) for GitHub
  access/refresh tokens at rest; HMAC-signed session cookie values (server-side
  session records only); `HttpOnly`, `SameSite=Lax`, `Secure` in production,
  expiry and revocation; Origin-validation middleware rejecting cross-origin
  unsafe requests for cookie-authenticated sessions (CSRF: `CSRF_ORIGIN_REJECTED`).
- **Auth API** (`/api/v1/auth/…`): `github/start` (one-time state, 503 envelope when
  the app is unconfigured), `github/callback` (backend-only code exchange, user
  upsert keyed on GitHub numeric ID, session cookie issuance, failure redirect
  with stable error code), `me` (200 `SessionState`; unauthenticated = 200 +
  `authenticated:false` per contract — note for Sameeksha), `logout` (204,
  revokes server session, clears cookie, 401 envelope when not signed in).
- **GitHub provider** (`services/github/client.py`): injectable
  `GitHubOAuthProvider` interface; production `HttpxGitHubOAuthProvider` for
  github.com OAuth token exchange + user profile; never logs payloads that may
  echo credentials.
- Strict CORS from settings (`allow_credentials=True`, explicit origins/methods/headers).

## Known issues, blockers, assumptions

- **GitHub verification is mocked-provider only** in automated tests (as required);
  a real GitHub App smoke test is pending Phase 3A / `docs/github-app-setup.md`.
- Token refresh/expiry handling: tokens are stored with `expires_at`; the refresh
  flow itself is Phase 3A work when GitHub API calls need live tokens.
- `/auth/me` returns **200 with `authenticated:false`** for absent/expired/invalid
  sessions (per the `SessionState` contract), not 401 — Sameeksha should design
  the session hook around this. 401 applies to `/logout`.
- SQLite stores naive datetimes; model validity checks normalize to UTC
  (`app/db/base.ensure_aware`). PostgreSQL remains the preferred deployment DB.
- `.env.example` documents required variable names; `SESSION_TTL_SECONDS` /
  `OAUTH_STATE_TTL_SECONDS` are optional with safe defaults.
- Root README/CI are unchanged (shared ownership; coordination required).
